### Key Code Findings

#### Bug A: LIFF Reserved Param Collision
```ts
// middleware.ts (line ~36) — BROKEN
liffUrl.searchParams.set('liff.state', pathname + (request.nextUrl.search || ''));

// navigation-provider.tsx (line ~44) — BROKEN
params.set('liff.state', state);
return `/liff?${params.toString()}`;
```
`liff.state` คือ Parameter ที่ LINE LIFF SDK ใช้เอง เมื่อ `liff.init()` พบ `?liff.state=%2Fprofile` ใน URL ปัจจุบัน มันตีความว่านี่คือ Redirect จาก LIFF Platform และ reconstruct endpoint URL เป็น `/liff/profile` ซึ่งไม่มี Route อยู่จริง → HTTP 404

#### Bug B: Browser Login Gate Deadlock
```ts
// app/liff/page.tsx (line ~67) — BROKEN
if (liff.isInClient() && !liff.isLoggedIn()) {
  liff.login({ redirectUri: window.location.href });
  return;
}
```
`liff.isInClient()` คืนค่า `false` เมื่อ LIFF App ไม่ได้เปิดใน LINE Browser (ซึ่งเป็นกรณีปกติทั่วไปบน Desktop/Mobile Browser) → เงื่อนไขไม่ผ่าน → `liff.getAccessToken()` → `null` → `router.replace(target)` → กลับหน้าเดิมโดยไม่มี Login

### Architecture Decisions
- **[DECISION] Rename Reserved Param**: ใช้ชื่อ `mmv_next` แทน `liff.state` ทุกจุดในโค้ด App-level เพื่อหลีกเลี่ยง SDK Conflict
- **[DECISION] Remove `isInClient()` Guard**: เรียก `liff.login()` ทุกครั้งที่ `!liff.isLoggedIn()` ไม่ว่าจะเป็น Browser หรือ LINE App — SDK รองรับทั้งสองกรณี

## Lessons Learned
- **Pattern (CRITICAL)**: ชื่อ Query Param ที่ใช้ร่วมกับ Third-party SDK ต้องตรวจสอบ Reserved Keywords ก่อนเสมอ — โดยเฉพาะ `liff.*` สำหรับ LINE LIFF
- **Pattern**: `liff.isInClient()` ใช้สำหรับแยก UX ไม่ใช่สำหรับ Gate Authentication — `liff.isLoggedIn()` เป็น Single Source of Truth สำหรับ Login State
- **Mistake**: Green Unit Tests บน Pure Logic ≠ การทำงานถูกต้องของ SDK Integration — ต้องมี E2E / Manual Smoke Test บน Real Device
- **Discovery**: LIFF SDK intercepting `?liff.state=` ใน URL เป็น Documented Behavior แต่ไม่มี Warning ชัดเจนในหน้า Docs — ต้องรู้ก่อนตั้งชื่อ Param
