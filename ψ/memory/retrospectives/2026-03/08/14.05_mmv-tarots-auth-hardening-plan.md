# Session Retrospective: Auth Hardening Strategy & Referral LIFF-Wrapping

**Time**: 2026-03-08 14:05 (+07)
**Project**: [projects/mmv-tarots](../../../../projects/mmv-tarots)
**Status**: ⏸️ Phase 5 Blueprint Finalized (Auth Ready)

## 🎯 Objective
Ground the current authentication state and finalize the implementation plan for Phase 5 (Auth & Session Hardening) to ensure a robust, LIFF-first user experience.

## 🛠️ What Actually Happened
- **Auth Grounding**: Confirmed 100% migration to LINE LIFF v2 with **Transparent Auth**. Verified that `LiffProvider` and `api/auth/liff-verify` are the core engines.
- **Bug Discovery**: Identified a critical redirect flaw where `window.location.reload()` in `LiffProvider` clears the `liff.state` parameter, causing users to get stuck at the root (`/`) instead of their intended sub-route (e.g., `/history`).
- **Referral Audit**: Validated that `middleware.ts` correctly intercepts `?ref=` and sets `mmv_ref` cookies, but identified that current referral links are standard web URLs which break the LIFF ecosystem on mobile.
- **Strategic Pivot**: Decided to delay the Payment UI implementation to prioritize **Auth Stability & Clean-up**.
- **Blueprint V3**: Drafted and finalized a comprehensive plan ([2026-03-08_13-02_phase5-implementation-plan.md](../../logs/mmv-tarots/2026-03-08_13-02_phase5-implementation-plan.md)) covering:
    - [x] Dedicated `/liff` entry point.
    - [x] Removal of legacy `signIn.social` calls.
    - [x] Redirect logic upgrade using `router.replace(liff.state)`.
    - [x] Referral LIFF-wrapping (`https://liff.line.me/{id}/path?ref=code`).

## 💡 Key Decisions
1. **Gateway over Interception**: Opted to create a dedicated `/liff` route as the official Auth Gateway to handle edge-case 404s and deep-linking.
2. **LIFF-First Referral**: Decided to wrap all referral links in the `liff.line.me` scheme to ensure they always open inside the LINE in-app browser with a valid LIFF context.
3. **Cookie Enforcer**: Decided to move from "Passive Auth" to "Active Middleware Enforcement" for sensitive routes.

## 🚧 Friction & Blockers
- **Terminal Encoding**: Encountered a severe `ZSH` encoding error during a `cat` heredoc operation which corrupted the blueprint file, requiring a manual recovery using `create_file`.
- **404 Route**: Confirmed that the production URL `https://maemormimi.com/liff` currently returns 404 because the route hasn't been implemented yet.
