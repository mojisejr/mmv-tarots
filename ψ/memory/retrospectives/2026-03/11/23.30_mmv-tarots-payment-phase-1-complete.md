### Key Code Changes
- **PaymentOrder Model**: Introduced a structured state machine for tracking payments from creation to fulfillment.
- **CreditTransaction Refactor**: Decoupled from gateway-specific IDs (Stripe/Omise) in favor of a generic `externalRef` and `channel` mapping.
- **Idempotent Fulfillment**: Updated `CreditService` to look up existing transactions via `externalRef` before adding stars.
- **Migration Strategy**: Used raw SQL in the migration to move legacy `omiseChargeId` and `stripeSessionId` into the new `externalRef` field and `metadata` JSON to ensure no data loss.

### Architecture Decisions
- **Unified Ledger**: Chose to keep `CreditTransaction` as the single source of truth for star balance, but linked it to `PaymentOrder` for the payment lifecycle.
- **Gateway Abstraction**: Moved gateway-specific logic into the `channel` field, allowing the system to handle any provider through a unified interface.
