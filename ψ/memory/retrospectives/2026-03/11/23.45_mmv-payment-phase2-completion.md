## Technical Details

### Files Modified
- `prisma/schema.prisma`: Added `PaymentOrder`, `PaymentVerificationLog` and redefined `CreditTransaction`.
- `lib/server/services/payment-order-service.ts`: Order creation and retrieval logic.
- `lib/server/services/slip-verification-service.ts`: SlipOK provider adapter.
- `lib/server/services/payment-fulfillment-service.ts`: Idempotent state machine for crediting stars.
- `app/api/payment/orders/route.ts`: Creation endpoint.
- `app/api/payment/orders/[id]/slip/route.ts`: Upload & verification entrypoint.
- `app/api/payment/orders/[id]/status/route.ts`: Progress polling.

### Key Code Changes
- **Payment Fulfillment Logic**: Used `db.$transaction` with a unique constraint check on `paymentOrderId` in `CreditTransaction` to prevent double-crediting if a slip is verified multiple times.
- **SlipOK Adapter**: Implemented a 10s timeout using `AbortController` to prevent serverless function hangs and added generic error mapping (e.g., `AMOUNT_MISMATCH`).

### Architecture Decisions
- **Unified Satang Strategy**: Chose to use a fixed amount for PromptPay generation but enforce exact amount matching on the server-side verification to ensure zero revenue leakage.
- **Provider Normalization**: Abstracted SlipOK into a `VerificationProvider` enum to allow future multi-provider support (e.g., adding bank-direct APIs later).
