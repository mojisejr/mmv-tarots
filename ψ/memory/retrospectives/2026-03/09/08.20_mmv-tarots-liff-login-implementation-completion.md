### Key Code Changes
- **Namespace Change**: เปลี่ยน `liff.state` เป็น `mmv_next` เพื่อป้องกัน LIFF SDK แทรกแซงและ reconstruct URL ผิด (สาเหตุของ 404 /liff/profile)
- **Login Unblock**: ลบ `isInClient()` ออกจาก `liff.login()` logic เพื่อให้ Browser ปกติเรียกหน้า OAuth ของ LINE ได้
- **Race Guard**: ใช้ `usePathname()` ใน `LiffProvider` เพื่อสั่งห้ามรัน bootstrap หากอยู่ที่หน้า `/liff` ป้องกันการ init ซ้อนชนกับหน้า Gateway

### Architecture Decisions
- **Custom Param Namespace**: ตัดสินใจใช้ `mmv_next` แทนพารามิเตอร์มาตรฐานของ SDK เพื่อความเป็นอิสระและหลีกเลี่ยงพฤติกรรม "Auto-cleansing" ของ SDK
- **Route-based Early Return**: เลือกที่จะ skip `LiffProvider` ทั้งก้อนบน route เฉพาะทาง แทนที่จะใส่ logic ซับซ้อนข้างใน เพื่อความชัวร์ว่าจะมีแค่ entry point เดียวที่คุม SDK

## What Could Improve
- **Async State Awareness**: ควรระวัง `isPending` ของ `useSession` มากกว่านี้ใน `LiffProvider` เพราะมันอาจเปิดช่องให้ logic ไหลผ่านไปถึง network-call ทั้งที่ยังไม่มีข้อมูลที่ถูกต้อง
- **Terminal Noise**: บางช่วงการรัน build ซ้ำๆ กินเวลา และอาจย่อรวมคำสั่งได้ดีกว่านี้เพื่อประหยัด Token

## Blockers & Resolutions
- **Blocker**: LIFF SDK ลบ `liff.state` ออกจาก URL ทันทีที่ init ทำให้ Gateway อ่านค่าไม่ได้
  **Resolution**: ย้ายไปใช้ `mmv_next` ซึ่ง SDK ไม่ยุ่งด้วย
- **Blocker**: `isInClient()` return `false` บน Chrome ทำให้ UI ติดอยู่หน้า Gateway ตลอดกาล
  **Resolution**: ลบ guard ทิ้งและเช็คเฉพาะ `isLoggedIn()` ซึ่งเป็นความจริงที่สำคัญที่สุด

## Lessons Learned
- **Pattern**: **Reserved Param Isolation** - การแยกชื่อตัวแปรที่ app ใช้ ออกจากตัวแปรที่ SDK/Platform ใช้ เป็นเรื่องสำคัญมาก
- **Mistake**: **Implicit Guard Assumption** - การคิดว่า `isInClient()` ครอบคลุมทุกเคสที่ควร login จริงๆ แล้วเป็นความผิดพลาด เพราะ Browser ก็ต้อง login ด้วย
- **Discovery**: **Provider Escape** - บางครั้งการ "สั่งห้าม" Provider ทำงานในบาง Route (Route-exclusion) สะอาดกว่าการพยายามทำให้ Provider ฉลาดทุกเรื่อง
