## 🧠 Decisions & Consensus
1. **Decision: Keep Better-Auth as Single-Core Engine**  
   - **Reasoning**: ถึงแม้ Better-Auth จะมีความซับซ้อนในตัว แต่การมี Middleware และ Client SDK ที่พร้อมใช้งานทำให้เสถียรกว่าการเขียน JWT Session เองทั้งหมดในระยะยาว
   - **Action**: ยุบรวมการสร้าง Session (Session Issuance) ให้ผ่าน Better-Auth Official API เท่านั้น และเลิกใช้ `serializeSignedCookie` (custom layer) ที่เป็นสาเหตุของ Cookie mismatch.

2. **Decision: Robust State Handling for Redirects**  
   - **Reasoning**: LIFF SDK มักทำ URL Params หายระหว่าง OAuth Round-trip
   - **Action**: เปลี่ยนไปใช้ Durable State (Key-based fallback) เพื่อกู้คืน `mmv_next` target เมื่อกลับมาที่ `/liff`.

3. **Decision: Integrated Phase 5 (Dead Code Cleanup)**  
   - **Reasoning**: โค้ดเก่าที่ทำหน้าที่ dual-cookie หรือ hardcoded session names ทำให้เกิด Technical Debt และความสับสนในการ Debug
   - **Action**: เพิ่มเฟสล้างบางโค้ดเก่า (`serializeSignedCookie`, `SESSION_COOKIE_NAME`) หลังจากการ Refactor เฟส 1-4 สำเร็จ.
