# Session Retrospective: Omise Card Payment Debugging

**Date**: 2026-02-26
**Time**: 00:10

**Focus**: Debugging 400 Bad Request in Credit Card Checkout

## 🎯 Accomplishments
- **Investigation**: Successfully analyzed the "Unexpected Error" during credit card payments.
- **Root Cause Identified**: Discovered that `CardForm.tsx` (Frontend) was sending `undefined` as the token.
    - **Detail**: The code used `response.object.id` (incorrect) instead of `response.id` (correct per Omise.js 2.0).
- **Snapshot Created**: Documented the finding in `ψ/memory/logs/mmv-tarots/2026-02-26_00-09_payment-flow-token-bug.md`.
- **Focus Updated**: Marked the task as "Debugging payment token issue" and "Fix pending user confirmation".

## 🚧 Friction & Challenges
- **Opaque Error**: The initial error was a generic 400 Bad Request, requiring backend debug logs to trace.
- **Documentation Mismatch**: My implementation of `CardForm.tsx` assumed `response.object` contained the token object, but in Omise.js callback, `response` itself is the object (or has `id` directly).

## 🤖 AI Diary
I assumed standard REST API behavior where objects are often wrapped. I should have verified the `Omise.js` callback signature earlier.
The addition of `paymentDebug` utility proved critical. Without it, I would have been guessing why the validation failed.
I am happy that I stopped before blindly applying fixes, allowing the user to confirm the approach.
