### Architecture Decisions
- Decision 1: **Adopt-then-Retire** — ยังไม่รื้อ Stripe ทันที เพื่อคงเสถียรภาพช่วงเปลี่ยนผ่าน
- Decision 2: **Custom UI First** — ไม่ใช้ default modal/hosted feel เพื่อรักษาแบรนด์และ UX consistency
- Decision 3: **Decommission as explicit phase** — เพิ่มงานปิดระบบ Stripe แบบมีเงื่อนไขหลัง Omise เสถียร

- [Decision clarity]: แยก “เริ่มใช้ Omise” ออกจาก “ถอด Stripe” ชัดเจน -> ลดความเสี่ยง rollout ผิดจังหวะ

  **Resolution**: สรุปแนวทาง Adopt-then-Retire และเสนอเพิ่มเฟสปิดระบบภายหลัง

## Lessons Learned
- **Pattern**: ถ้าจะเปลี่ยน payment provider ให้แยก phase ปรับใช้กับ phase ถอดระบบเสมอ - ลด outage และ rollback pain
- **Mistake**: ปล่อยคำว่า “complete plan” โดยไม่มี decommission criteria - เสี่ยงตีความผิด
- **Discovery**: การ lock คำว่า “Custom Form Only” ช่วย alignment ข้ามทีมได้เร็วมาก - ใช้กับทุกงานที่มี UI compliance
