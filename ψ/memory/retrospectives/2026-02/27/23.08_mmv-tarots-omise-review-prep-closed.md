## What Went Well
- Grounding จากโค้ดจริงก่อนให้คำตอบ ทำให้ข้อความฟอร์มไม่หลุดจาก implementation
- แปลงคำอธิบายเชิงเทคนิคเป็นภาษาฟอร์ม compliance ที่กระชับและปลอดภัย
- ยืนยันจุดเสี่ยงที่คนพลาดบ่อย: webhook setup แยก test/live, reviewer login path, และ refund wording

## What Could Improve
- ควรมี checklist แบบ single-page สำหรับ Omise review ใน repo เพื่อใช้ซ้ำ
- ควรเพิ่มเอกสาร public policy links (ToS/Refund/Privacy) ให้ตรวจง่ายก่อนยื่น

## Blockers & Resolutions
- **Blocker**: ความกำกวมระหว่าง “ระบบรองรับ” กับ “สิ่งที่ควรติ๊กในฟอร์ม”
  **Resolution**: ยึด source-of-truth จาก route/auth code แล้วแนะนำเฉพาะ capabilities ที่มีจริง
- **Blocker**: ฟอร์มบางช่องบังคับ username/password แต่ระบบใช้ LINE OAuth
  **Resolution**: ระบุ reviewer note ว่า OAuth-only และเสนอ assisted access wording
