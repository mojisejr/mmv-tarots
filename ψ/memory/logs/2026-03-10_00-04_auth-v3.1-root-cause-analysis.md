# Snapshot: Root Cause Analysis - mmv-tarots Post-Login Loading Hang

**Time**: 2026-03-10 00:04 +0700
**Project**: [mmv-tarots](projects/mmv-tarots)
**Context**: Deep-dive วิเคราะห์ปัญหาการค้างที่หน้า Loading หลัง Login สำเร็จ (Phase 5 Completion) โดยใช้ Grounding + Web Search เพื่อสรุปสาเหตุและแนวทางแก้ไขที่น่าเชื่อถือที่สุด

## 🔬 Root Cause Analysis (Two-Layer Bug)

### 1. Client-Side Session Sync Gap (Layer 1)
- **Problem**: การใช้ `router.replace(target)` หลังจากการทำ Manual Auth Bridge ใน `/api/auth/liff-verify` ทำให้ Better-Auth Component Client (React) ไม่รับรู้ว่า Cookie ถูกเซ็ตแล้ว
- **Reason**: `router.replace` เป็น Soft Navigation ซึ่งจะไม่ Remount Layout หรือ Invalidate Local Atoms ของ Better-Auth ทำให้ `useSession()` ยังคงคืนค่า `null` จาก Cache เดิม จนกว่าจะมีการ Revalidate ตามเงื่อนไขอื่น (เช่น Visibility Change)
- **Evidence**: พฤติกรรมที่ "รีเฟรชแล้วบางครั้งหาย" เกิดจากการ Force Re-read Cookie โดยตรงจากการโหลดหน้าใหม่ (Hard Reload)

### 2. Global Loading State Deadlock (Layer 2)
- **Problem**: Logic ใน `isInitialLoading` ของ `NavigationProvider` ทำให้เกิด Infinite Overlay หากการ Fetch Balance ล้มเหลวหรือล่าช้า
- **Code Reference**: `const isInitialLoading = isPending || (isLoggedIn && stars === null);`
- **Fatal Chain**:
    1. Auth Bridge สำเร็จ -> `isLoggedIn` กลายเป็น `true` (หลังจาก Client Sync สำเร็จ)
    2. `refreshBalance()` ถูกเรียก แต่หาก Network ใน LINE IAB ขัดข้องหรือ Timeout
    3. `stars` จะยังคงเป็น `null` (ตาม Error Block ในโค้ดปัจจุบันที่แค่ Log แต่ไม่ Set state สำรอง)
    4. `isInitialLoading` จะถูกขังอยู่ที่ `true` ตลอดไป ทำให้ `GlobalLoading` ไม่หายไปจากหน้าจอ

## ✅ Decisive Solution

### A. Hard Navigation for Bridge Success
- เปลี่ยนจาก `router.replace(target)` เป็น `window.location.href = target` ใน success path ของ `liff/page.tsx` เพื่อบังคับให้ Browser อ่าน Cookie ใหม่และเริ่มต้น Client State จากศูนย์ที่สะอาดที่สุด

### B. Defensive Loading State
- แยกระหว่าง "สถานะการตรวจสอบ Session" และ "สถานะการดึงข้อมูล Balance" ออกจากกันอย่างเด็ดขาด
- ใช้ `.finally(() => setBalanceFetched(true))` ในการเคลียร์ Loading Guard ไม่ว่าจะ Fetch Success หรือ Fail เพื่อให้แอปพลิเคชันยังคง Interactive ได้เสมอ

## 🛡️ Apply When
- แก้ปัญหา Authentication Bridge ที่ทำงานระหว่าง Auth Provider (Better-Auth) และ Custom Middleware/APIs
- ปรับปรุงความทนทานของหน้าแรก (Home) ต่อสภาวะเครือข่ายที่ไม่เสถียรใน LINE In-App Browser

## 🚀 Next Actions
1. Implement Hotfix ใน `NavigationProvider` (Add `balanceFetched` state)
2. เปลี่ยน Redirect Logic ใน `liff/page.tsx` เป็น `window.location.href`
3. เพิ่มความยืดหยุ่นใน `refreshBalance` (Set fallback stars ถ้า fetch fail หลัง login)
